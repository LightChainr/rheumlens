### P0-1 Figure 8 仍是旧版逻辑 —— **确认，而且比意见描述的更严重**

意见指出图内残留 `Revised:`、`stratified/unstratified permutation`、`design strata`、
`tuned ≈ frozen AUC`、`model-selection artefact`。核实全部属实。

比意见更严重的一点：**Q0 与 C0 把 `tuned ≈ frozen AUC` 写成了可行性门槛**，而这个门槛
（旧的 0.20 规则）已经在上一轮从分析代码里删掉了。也就是说这张主图在重新引入一条正文
已经明确撤回的判定规则，同时把 `model-selection artefact` 写成停止条件——这条措辞也是
撤回过的。

**落实：**重画 Figure 8，不改任何分析。

| 节点 | 旧 | 新 |
|---|---|---|
| Q0 | `stratified permutation defined AND tuned ≈ frozen AUC` | `a collection stratum holds both labels, AND the recorded metadata does not separate the labels exactly` |
| C0 | `... or the AUC is a model-selection artefact` | `No collection stratum holds both labels, or the metadata separates them exactly` |
| Q1 | `beat the unstratified permutation` | `beat the free permutation` |
| Q2 | `exceed the stratified permutation / within design strata` | `beat the collection-preserving permutation / within collection strata only` |
| Q3 | `design-diagnosis link weak ... p(V_D)` | `metadata-diagnosis link weak: design-only AUC near chance and not beyond its own null` |
| Q4 | `mixed design × label strata exist?` | `a collection stratum large enough to restrict to?` |
| C2 | `CONSISTENT WITH DESIGN ALONE` | `CONSISTENT WITH THE COLLECTION STRATA` |
| Route A | `ADJUST · 残差化是主结论` | `WEAK NUISANCE · 可以调整，但必须同时报告代价` |
| 副标题 | `Revised: ...` | 去掉版本史措辞 |

**Route A 是我自己额外改的。**旧措辞是「设计是普通的 nuisance，残差化是主结论」。但 §3.5
和 Figure 6C 恰恰证明：CMV 队列没有可移除的东西，残差化仍然拿走 0.282 AUC。图与正文互相
矛盾，且矛盾方向对我们不利（图在推荐一个正文证明有害的做法）。新措辞改为「几乎没有东西
可移除；要调整就必须同时报告代价」。

### P0-3 置换次数与最小 p 值不一致 —— **确认，正文错，代码对**

核实：`run_design_screen.py` 中 `N_PERM = 1000`；实际结果表里 `p_free` /
`p_collection_preserving` 的最小值就是 **0.001**，`p_design_auc` / `p_V_D` 的最小值是
**0.005**。也就是说 **2,000 次置换从来没有跑过**，`0.0005` 与 `1/2000` 是纯粹的文字残留。

**落实：**改回 complete-pipeline 1,000 次（floor = 1/1001 ≈ 0.0010）、V_D 与 design-only
AUC null 200 次（floor = 1/201 ≈ 0.0050）。同步修 Table 1 图注、§4.2、§6.1、§9.4、
Table S7、Figure 3D 的坐标轴刻度（原来画着一个 0.0005 的刻度，而没有任何点能落在那里）。

### P0-7 Table S6（原 S5）与正文描述不匹配 —— **确认，而且比意见描述的更严重**

意见说这张表只有 5 行、多列为空、没有 verification_date。核实属实，另外还发现：
**这张表的列根本是错位的**——`collection` 列里放的是供者数，`n_donor` 列里放的是病例标签，
`download_gb` 列里放的是 `medium`/`strong`，`case_labels` 列里放的是文献引用。

**落实：**采用意见的首选方案，新增 `tools/build_registry_table.py` 自动生成：

- 标识符、引用、发布供者数、下载体积、核验日期 ← `cohorts/registry.yaml`（CELLxGENE API 响应）
- **实际建模的供者/病例/对照数 ← 真正拟合用的 `donor_labels.tsv` 逐个数出来**
- 只在 §5 使用的两个数据集（GSE135779、GSE285773）补进来，并标注来源是 GEO、非 API 核验

现在是 7 行、每个字段都有值，脚本内含断言：任一字段为空即失败。发布供者数与实际建模数
**分列**（如 Ren 196 vs 182），因为二者本来就不同，合成一个数才是误导。九个对比的
供者/病例数与主筛查输出逐一吻合。
