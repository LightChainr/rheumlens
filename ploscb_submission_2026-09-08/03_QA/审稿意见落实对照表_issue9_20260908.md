## P0-1 / 补充意见 1：设计变量里是否混入诊断标签

**核实结论：部分确认。Table S2 确实错了，但模型矩阵里没有标签，不存在泄漏。**

`run_design_screen.py:design_matrix()` 用的是**白名单**，不是黑名单：

- `qc_cols` = `log_cells_per_donor`, `log_mean_umi_per_cell`, `log_mean_genes_per_cell`, `aggregate_pct_mito`
- `demo_num` = `age_years`；`demo_cat` = `sex`, `ethnicity`
- `batch_cat` = 所有 `batch__*` 前缀列，`assay` 取值多于一个时加入

`case_control` 既不在任一列表里，也不以 `batch__` 开头，因此**任何情况下都进不了模型矩阵**。
`processing_fraction_*` 同理。旧 Table S2 是手工维护的、按列名启发式分类的**协变量文件清单**，
不是模型矩阵清单——它把凡是不像人口学/采集的列一律归到 "sample quality"，于是
`case_control` 被错误地列在那里。

**落实：**

- 新增 `audit/build_design_manifest.py`，直接 import 真实的 `design_matrix()` 生成清单。
- 机器校验：清单推算的列宽与实际拟合的模型矩阵列宽**逐块比对，34/34 全部一致**；
  任何标签列出现在任一块中的次数 **0**。
- Table S2 换成生成的 manifest；新增 Table S2b 列出协变量文件中未进入任何块的列及原因。
- 正文 §4.1 写明这一校验及其结果。

## P0-2 / 补充意见 3：分层置换没有保住完整设计–诊断关联

**核实结论：确认。**

`design_strata()` 只用 `batch__*` × `assay`（无采集变量时退化为 `log_cells_per_donor` 三分位），
而声明的设计矩阵还含 QC 与人口学列。所以该检验保住的是**采集变量**与诊断的关联，
不是完整 D–Y 关联。原来写成 "design-preserving"、并据此声称存在 "design-independent
component"，是超出证据的。

**落实（走 issue 给的 A 路径，并补 B 路径要求的校准）：**

- 全文改名：`design-preserving` → **collection-preserving**；`unstratified` → **free**。
  函数改名 `design_strata` → `collection_strata`，并**返回它自己的分层定义字符串**，
  写进结果表 `strata_definition` 列，使名称与实现不能各说各话。
- §2.3 新增 "What it preserves, and what it does not" 段落，明确 QC 与人口学列不在条件集中。
- §9.6 写明：无采集变量的队列退化为 QC 三分位时，该检验是"样本质量保持置换"，如实标注。
- **新增针对性模拟（§3.4，Figure S6，Table S1）**：层内仍有质量混杂、且生成模型中
  **完全没有疾病效应**时，测量该检验的假阳性率（200 donors，8 个采集点，300 次重复，
  每次 200 置换）。结果：γ = 0 时两个检验都是校准的（collection-preserving 6.7%，
  95% CI 4.4–10.1；free 7.7%，5.2–11.2；名义 5%）；但只要质量变量在层**内**与诊断有关联，
  两个检验的拒绝率就一起上升——层内 |corr| = 0.29 时到 15.7% / 17.3%，0.61 时两者都到 89.3%。
  也就是说 **collection-preserving 检验并不比 free 检验更能防住层内混杂**。这正是补充意见 3
  点名要求的那个模拟，结论对我们不利，照写。
- 删除所有 "design-independent component" 措辞。

## P0-3 / 补充意见 2：V_D 与 p(V_D) 用的不是同一个统计量

**核实结论：确认。**

`label_information_fraction()` 返回交叉拟合的 `i_d_cv`，但 p 值由**样本内** `i_d_in`
与样本内零分布比较得到。两侧各自内部一致，但正文把它们当成一个推断量来写。

**落实（走 issue 的 preferred 路径）：**

- 每次置换都推过**同一组折**重算交叉拟合统计量，`p_i_d` 现在是交叉拟合量对交叉拟合零分布。
- 样本内那一对完整保留并改名 `p_V_D_insample`，与交叉拟合对**永不混用**。
- §2.2、§9.4 改写。
- 顺带修正：正文原写 "in-sample R² 接近 1"，而 V_D=0.468 对应 R²=0.532。已改为实数。

## P0-5 / 补充意见 4：CMV 阴性对照的描述与事实不符

**核实结论：确认，且比意见指出的更严重。**

实测 `cmv_hiha_donor_covariates.tsv`：`batch__batch_id` **36 个水平**，`batch__pool_id`
**46 个水平**，交叉后 46 层、其中 17 层只有 1 名供者。`assay` 与 `suspension_type` 确实
各只有 1 个水平（"one chemistry" 属实）。但**每名供者只有一行、一个标签，全文任何地方都没有
做过供者内配对**——"donors paired against themselves" 不成立。

**落实：**

- §4.2 重写，逐项写出真实结构，并说明它之所以是阴性对照，靠的是**采集标签与诊断关联弱**，
  不是"单批次"。§9.1 与 Author Summary 中的相应措辞一并改掉。
- 人口学块的显著性：五个种子下 design-only AUC 0.611–0.625，置换 p = 0.005–0.075，
  即**部分种子显著、部分不显著，且过不了跨四个块九个对比的多重比较**。正文（§4.2）
  按这个区间原样报告，并解释性别与族裔本身就是 CMV 血清阳性率的已知相关因素，
  所以这一条更像 case mix 而不是研究设计。没有把它写成"不显著"。
- **"89 列除以 108 人所以移除了大部分信息" 这个机制解释，我去做了模拟检验而不是照写**（§3.5，
  Figure S5，Table S1）：D ⟂ Y、108 人、生物学效应校准到 CMV 的 0.845 时，同宽度（92 列）
  的平衡设计矩阵只造成 **0.045** 的损失；按 CMV 真实批次×池水平大小构造的 "ragged" 矩阵
  造成 **0.091**；损失对宽度**非单调**，在 48–64 列处达到峰值 0.222–0.229 后回落。
  三个数都明显小于真实观察到的 **0.282**。因此正文改成：宽度与不规则形状解释一部分，
  不解释全部，剩下的部分我们没有解释清楚，并把这一条写进 §8 Limitations。

## P0-6 / 补充意见 5：模拟中的两个结论

**核实结论：两条都确认。**

- `label_type == "continuous"` 只用于生成 X 中的表达信号；`cv_auc(D, y)` / `cv_auc(X, y)`
  用的自始至终是二元 `y`。所以那不是连续结局验证。
- `imbalanced` 臂把标签阈值改到 80 分位，但 `site = (z > 0)` 阈值没动。ρ=1 时二者不再重合，
  design AUC 的上限下降是**阈值错配**，不是患病率本身。

**落实：**

- 连续臂改为**真正预测连续结局**：ridge 回归，用 concordance index 评分（二元时恰等于 AUC，
  两臂因此在同一尺度上）。
- 不平衡拆成两臂：`imbalanced`（两个阈值都在 80 分位，只变患病率）与
  `imbalanced_offset`（标签 80 分位、采集边界在中位数，即现实中的错配）。
  预跑确认：修正后 `imbalanced` 在 ρ=1 恢复到 design AUC = 1.000，`imbalanced_offset` 为 0.866。
- 随机种子从 `hash()` 改为 `hashlib.blake2b` 派生，跨进程稳定，并把每格实际 seed 写入结果表。
